term: Run log
aka: [job log, execution transcript, build output]
kind: measure
plain: The ordered record of a run's status changes, commands, tool results, warnings, and final outcome. It is the first account of what happened. An unattended agent run can also keep a decision log, with one row per step that names the decision, the reason, and the evidence.
does: Lets a human locate the failing step and decide whether to retry, change the task, or stop the factory.
ask: Can someone reconstruct the run from trigger to final result without opening the runner?
cues:
  - "Timestamped steps with queued, running, and finished states"
  - "Command output, warnings, exit codes, and artifact links"
  - "A retention setting and a redaction marker"
range: "Keep enough history for review and incident response. GitHub Actions retains workflow logs for 90 days by default, with repository limits from 1 to 90 or 400 days."
trouble: "The log ends before the failure, hides the command that changed state, contains a secret, or disappears when an ephemeral worker is deleted."
